# Condo Ninja — project handoff

This document is the primary context for a developer or AI continuing the project outside ChatGPT Sites. Read it together with `AGENTS.md`, `README.md`, `.env.example`, and the current tests.

## Product and language

Condo Ninja is a Brazilian Portuguese product for condominium residents. Its promise is greater transparency, savings, and resident participation. The public website leads visitors to a free “Raio-X”; the restricted area supports account creation, onboarding, condominium profiles, private document uploads, progress, invitations, and future analysis modules.

Visible product copy and validation errors should be in Brazilian Portuguese. Preserve the current dark navy/blue visual identity, geometric ninja branding, motion details, responsive behavior, and Goldman logo typography unless a redesign is explicitly requested.

## Current architecture

- Next.js 16 App Router, React 19, TypeScript 6.
- Local/self-hosted mode: Node.js with `node:sqlite`; files and avatars are stored below `DATA_DIR`.
- ChatGPT Sites mode: Vinext/Vite on Cloudflare Workers; D1 stores structured data and R2 stores private files.
- Authentication is application-owned email/password authentication with signed random sessions. Password reset and email verification do not exist yet.
- Production migrations are generated by Drizzle and stored in `drizzle/`. Never rewrite a migration that may already have been applied; append a new migration.
- The local SQLite migration path is maintained in `lib/db.ts`. Schema changes generally need both `db/schema.ts` (hosted D1) and an additive local migration in `lib/db.ts`.

Important directories:

- `app/`: pages, layouts, API routes, marketing and restricted-area styles.
- `components/`: client and shared UI components.
- `lib/`: domain logic, local persistence, authentication, validation and storage.
- `hosting/`: adapters replacing local DB/config/avatar/file storage for Workers/D1/R2.
- `db/` and `drizzle/`: hosted schema and immutable migrations.
- `public/`: browser assets used by the application.
- `assets/`: source/reference audio, avatar prompts and marketing reference material.
- `tests/`: Vitest coverage; `e2e/`: Playwright desktop/mobile flows.

## Running locally

Requirements: Node.js 22.5 or newer (Node 24 recommended), pnpm, and Chrome for E2E tests.

```bash
cp .env.example .env.local
pnpm install --frozen-lockfile
pnpm setup
pnpm dev
```

Open `http://localhost:3000`. `pnpm setup` creates the SQLite database and private upload directory under `DATA_DIR`. Use an absolute persistent path for `DATA_DIR` on a server. Never serve that directory as static content.

Production-style Node deployment:

```bash
pnpm install --frozen-lockfile
pnpm setup
pnpm build:next
pnpm start
```

Provide at least `APP_URL`, a long random `AUTH_SECRET`, and a persistent `DATA_DIR`. Put the application behind HTTPS and a reverse proxy. Back up the SQLite database and uploaded files together. This local storage architecture is intended for one application instance; moving to multiple instances requires shared database/object storage and corresponding adapters.

## ChatGPT Sites build

The existing Sites project is declared in `.openai/hosting.json` and was published at `https://condo-ninja.calrtd.chatgpt.site`. The manifest contains only a project identifier and logical D1/R2 bindings; it contains no credentials.

```bash
pnpm build:sites
```

This produces a Worker build under `dist/`. Hosted environment values include `AUTH_SECRET` and `APP_URL`. Do not commit secrets. `hosting/db.ts` maps logical table names to the `cn_*` namespace. Existing D1 migrations are immutable.

For a different hosting provider, the simplest supported path is the Node/self-hosted mode. The Cloudflare/Sites adapters can also be adapted to ordinary Cloudflare Workers, but deployment wiring and bindings must be supplied by that host.

## Data and security boundaries

- Accounts, sessions, onboarding and document metadata are private.
- Uploaded documents are never placed in `public/` and no customer-facing download route exists.
- Upload validation checks extension, size, content signature and duplicates.
- Custom profile photos override default ninja avatars.
- Do not include or migrate `data/`, `.env*`, auth secrets, production database exports, uploaded documents, or access tokens in source archives.
- Registration/login uses email/password. Implement reset and email verification before treating authentication as production-complete.
- Rate limiting and mature production observability are still outstanding.

## Referral and ninja-level behavior

- `/app/convide` creates a stable opaque referral link per user and shares it through WhatsApp.
- `/convite/[code]` stores a signed, HTTP-only first-touch referral cookie for 30 days and redirects to the public homepage.
- Registration atomically records the inviter in `user_referrals`; an invalid code never blocks account creation.
- The first successful referred registration inserts `ninja_upgrades` for the inviter.
- On the inviter’s next page load, the client atomically claims the pending presentation. Only one tab/device can play it. Afterward the red avatar remains active and the animation does not repeat.
- The red transition uses `public/default-avatar-ninja-red.png`, a red glow, and `public/audio/11-reflexao.mp3`. Browser autoplay policy may suppress sound.
- “Começar Ninja vermelho” and the older ninja test control are development-only preview controls. They must not write to the database or appear in production.
- The WhatsApp destination currently points to the ChatGPT Sites domain. Change `siteUrl` in `app/app/convide/page.tsx` when moving production to a new canonical domain.

## Current UX decisions to preserve

- The public hero and marketing sections use the navy/blue cyber-futurist identity and responsive motion effects.
- Login and registration keep the existing email/password interface and animated card transition.
- The restricted sidebar has delayed one-way logo reveal on desktop; mobile shows icon and text directly.
- Completed document groups load collapsed but remain expandable.
- “Convide seus vizinhos” stays last in the main sidebar navigation, above the profile.
- Form errors are in Brazilian Portuguese.
- Reduced-motion preferences should disable nonessential animation.

## Verification before handoff or deployment

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm test:e2e
pnpm build:next
pnpm build:sites
```

The E2E suite starts an isolated server on port 3100 and uses `data/e2e`; it does not reuse the normal local database. Some address tests depend on external ViaCEP/IBGE availability.

## Known gaps and next work

- No password reset or email verification.
- No asynchronous document analysis pipeline yet; “Raio-X” analysis modules are largely future-facing UI.
- Local mode is not horizontally scalable.
- Rate limiting, audit/monitoring, backup automation and production incident tooling need completion.
- A custom production domain should replace the hard-coded Sites referral origin when the move is complete.
- Update `README.md` and `DEVELOPMENT_STATE.md` as features evolve; historical details there may lag this handoff.

## Asset provenance and prompts

Prompt notes for generated avatars are stored beside assets in `public/*.prompt.md` and `assets/archive/avatars/*.prompt.md`. Audio catalog notes are stored in the respective `assets/audio/**/README.md` files. Font licenses are included in `public/fonts/`.

## Instructions for another AI

1. Read `AGENTS.md` before editing Next.js code and consult the version-specific docs under `node_modules/next/dist/docs/` after installing dependencies.
2. Inspect the current file and tests before changing behavior; the working tree may contain user-owned changes.
3. Preserve existing user data and append migrations. Never reset or recreate a database as a shortcut.
4. Keep local and hosted adapters behaviorally equivalent when persistence or files change.
5. Use `apply_patch` for focused edits and run tests proportional to the change.
6. Do not commit secrets, local databases, uploads, build output or dependency directories.
7. Treat the code and tests as authoritative when older narrative documents conflict with implementation.
